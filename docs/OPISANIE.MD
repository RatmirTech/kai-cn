# Построчное описание Turbo Pascal-варианта курсовой работы

## 0. Почему исходный вариант был на C++

C++-вариант использует Win32 API:
- `WSAStartup`, `socket`, `bind`, `listen`, `accept`, `connect`, `send`, `recv` — WinSock;
- `Netbios()` и `NCB` — NetBIOS API Windows;
- `AF_IPX`, `NSPROTO_SPX` — IPX/SPX-сокеты Windows.

Turbo Pascal DOS не имеет WinSock. Поэтому в TP-варианте:
- NetBIOS вызывается через `Int 5Ch`;
- IPX/SPX вызывается через драйвер, точка входа которого находится через `Int 2Fh`, функция `AX=7A00h`;
- вызов драйвера оформлен в `IPX.ASM`, потому что из Turbo Pascal неудобно делать дальний вызов по адресу `ES:DI`.

## 1. Общие термины

### 1.1. NCB

`NCB` — Network Control Block, блок управления NetBIOS. Это структура из 64 байт. Поля:

| Поле | Размер | Возможные значения | Назначение |
|---|---:|---|---|
| `ncb_command` | 1 | `$30`, `$31`, `$32`, `$10`, `$11`, `$12`, `$14`, `$15`, `$20`, `$21` и др. | Команда NetBIOS. |
| `ncb_retcode` | 1 | `0`, `$FF`, коды ошибок | Немедленный код возврата. |
| `ncb_lsn` | 1 | `0..255` | Номер локального сеанса. Используется для `NCBSEND`, `NCBRECV`, `NCBHANGUP`. |
| `ncb_num` | 1 | `0..255` | Номер имени в таблице имён. |
| `ncb_buf_ofs` | 2 | `0..$FFFF` | Смещение буфера данных. |
| `ncb_buf_seg` | 2 | `0..$FFFF` | Сегмент буфера данных. |
| `ncb_length` | 2 | `0..$FFFF` | Длина буфера. |
| `ncb_callname` | 16 | 16 символов, дополненных пробелами | Имя вызываемой стороны. |
| `ncb_name` | 16 | 16 символов, дополненных пробелами | Собственное имя. |
| `ncb_rto` | 1 | `0..255` | Тайм-аут приёма. |
| `ncb_sto` | 1 | `0..255` | Тайм-аут отправки. |
| `ncb_post_ofs` | 2 | `0..$FFFF` | Смещение post-процедуры. |
| `ncb_post_seg` | 2 | `0..$FFFF` | Сегмент post-процедуры. |
| `ncb_lana_num` | 1 | обычно `0` | Номер адаптера LAN. |
| `ncb_cmd_cplt` | 1 | `0`, `$FF`, коды ошибок | Признак завершения команды. `$FF` — команда ещё выполняется. |
| `ncb_reserve` | 14 | служебные | Резерв. |

### 1.2. Основные команды NetBIOS

| Константа | Код | Значение |
|---|---:|---|
| `NCBRESET` | `$32` | Сброс адаптера и таблицы имён. |
| `NCBADDNAME` | `$30` | Добавить обычное уникальное имя. |
| `NCBADDGRNAME` | `$36` | Добавить групповое имя. |
| `NCBDELNAME` | `$31` | Удалить имя. |
| `NCBCALL` | `$10` | Установить сеанс с удалённым именем. |
| `NCBLISTEN` | `$11` | Ожидать входящий сеанс. |
| `NCBHANGUP` | `$12` | Завершить сеанс. |
| `NCBSEND` | `$14` | Отправить данные в сеансе. |
| `NCBRECV` | `$15` | Принять данные из сеанса. |
| `NCBDGSEND` | `$20` | Отправить датаграмму. |
| `NCBDGRECV` | `$21` | Принять датаграмму. |

`NRC_GOODRET = 0` — успешное завершение.

### 1.3. IPX/SPX-термины

| Термин | Значение |
|---|---|
| `IPX` | Interwork Packet Exchange, дейтаграммный протокол. |
| `SPX` | Sequenced Packet Exchange, потоковый протокол поверх IPX с подтверждениями. |
| Сокет | Номер порта IPX/SPX, 16 бит. В работе используются `$1000` и `$6555`. |
| Сеть | 4-байтовый номер сети IPX. |
| Узел | 6-байтовый MAC-адрес узла. |
| `TPacket` | Структура IPX/SPX-пакета. |
| `TECB` | Event Control Block, блок управления операцией IPX/SPX. |
| `InUse` | `0` — операция завершена; `<>0` — операция выполняется. |
| `CCode` | Код завершения операции. |
| `PacketType` | `4` — IPX-датаграмма; `5` — SPX-пакет. |
| `DataStreamType` | `$FA` — обычные данные SPX; `$FF` — завершение соединения. |

### 1.4. Команды драйвера IPX/SPX через `BX`

| `BX` | Значение |
|---:|---|
| `00h` | Открыть сокет. |
| `01h` | Закрыть сокет. |
| `10h` | Проверить установку SPX. |
| `11h` | Установить SPX-соединение. |
| `12h` | Ожидать SPX-соединение. |
| `13h` | Завершить SPX-соединение. |
| `16h` | Отправить SPX-пакет. |
| `17h` | Принять SPX-пакет. |

## 2. `IPX.ASM`

| Блок | Описание |
|---|---|
| `IPXSPX_REGS struc` | Структура регистров для обмена с драйвером. |
| `rax..res` | Поля регистров `AX,BX,CX,DX,SI,DI,ES`. |
| `EXTRN ipxspx_drv_entry` | Внешняя переменная — адрес точки входа драйвера. |
| `IPXENTR` | Процедура вызова драйвера. Сохраняет регистры, загружает `ES:DI` как адрес структуры, вызывает драйвер, сохраняет результат обратно. |
| `IPXINIT` | Получает адрес драйвера через `Int 2Fh`, `AX=7A00h`. |
| `ret 2` | Возврат с очисткой параметра. |

| `CheckIPX` | Проверка IPX. |

## 7. Порядок сборки и запуска

1. Собрать `IPX.ASM`:
   ```text
   tasm /m2 IPX.ASM
   ```
2. В Turbo Pascal подключить `{$L IPX.OBJ}`.
3. Скомпилировать:
   - `SPX_C.PAS` — на XP1;
   - `GATEWAY.PAS` — на XP2;
   - `NETBIOS_DG_S.PAS` — на XP3;
   - `NETBIOS_CN_S.PAS` — на XP3.
4. Запустить на XP3 оба сервера NetBIOS.
5. Запустить на XP2 `GATEWAY.EXE`.
6. Запустить на XP1 `SPX_C.EXE`.
7. Ввести адрес сети и узла шлюза.
8. Вводить сообщения; `exit` завершает работу.

## 8. Ограничения

- В C++-варианте шлюз отправляет сообщения в две ветви поочерёдно. В TP-варианте это сохранено.
- Если требуется отправлять каждое сообщение сразу в обе ветви, нужно убрать переключение `IsFirst/IsSecond` и всегда вызывать оба блока отправки.
- Адреса и сокеты можно изменить в константах и в вызовах `IPXOpenSocket`/`SPXEstablishConnection`.
